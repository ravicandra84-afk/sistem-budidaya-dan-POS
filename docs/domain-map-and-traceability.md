## Aturan Interpretasi

- Untuk hak akses Receiving, keputusan eksplisit Owner tanggal 2026-11-17 dalam [AGENTS.md](../AGENTS.md) berlaku: pembuatan oleh `Owner`, `Admin Operasional`, dan `Kepala Budidaya`; VOID oleh `Owner` dan `Admin Operasional`.
- Baris `FR-REC-06` dan `FR-REC-07` di [prd.md](../prd.md) masih memuat daftar role lama. Kode saat ini dan keputusan Owner terbaru mengikuti aturan di atas; matriks PRD perlu disinkronkan pada pekerjaan dokumentasi tersendiri.
- Rumus stok mencakup sumber yang tersedia; saat ini `current_stock` berasal dari penerimaan valid dikurangi Receiving VOID. Penjualan belum tersedia dan mortalitas di luar MVP, sehingga keduanya tidak dibuat sebagai sumber atau tabel.

### Relasi Receipt, Batch, Status, dan Stok

- `batches` ke `incoming_fish`: tepat 1:1. `incoming_fish.batch_id` memiliki unique constraint (paling banyak satu receipt) dan deferred constraint trigger mengharuskan receipt ada saat commit (paling sedikit satu).
- `incoming_fish` ke `incoming_fish_voids`: 0:1; VOID tidak menghapus atau mengubah receipt asli.
- Pembuatan receipt membuat batch berstatus `active`; Receiving VOID membuat record reversal dan mengubah batch menjadi `voided`.
- Database membatasi status ke `active`, `completed`, `voided`, menolak `completed` saat computed stock positif, dan memvalidasi transisi. Stok tersedia melalui `current_stock` pada API/list/detail.
- Database dan service menghitung penerimaan valid dikurangi Receiving VOID. Sales dan mortality belum menjadi sumber transaksi sampai modulnya disetujui dan tersedia.

## Gap dan Catatan Verifikasi

1. TC-01..32 lulus pada full PostgreSQL run (121/121 tests); TC-20/28 memakai injected dependency stub dan tidak membuat POS DDL/API.
2. Sumber stok V4.5 kini dihitung dari receipt dan Receiving VOID; sales/mortality tetap belum tersedia. Backup/restore rehearsal masih menjadi blocker Gate.
3. TC-07 p95 lulus pada host dev lokal berkapasitas nominal 4 vCPU/7.45 GiB; benchmark staging terkelola belum dijalankan.
4. `pfi_db` tetap utuh pada 2 migrasi sebelumnya; migration computed-stock baru diterapkan hanya di `pfi_test` dan masih pending operasional.
5. Backup/restore rehearsal tidak dapat dijalankan karena native PostgreSQL backup/restore utilities tidak terpasang.
6. Konflik role lama pada tabel PRD `FR-REC-06/07` tetap dicatat; Master Blueprint §2.3 dan implementasi mengikuti keputusan Owner terbaru.
