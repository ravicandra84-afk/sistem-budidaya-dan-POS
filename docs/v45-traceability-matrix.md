## Reading the Matrix

- `Implemented` identifies a source-code or schema location; it does not mean the behavior passed an executed test.
- `Test defined` means a corresponding case exists in [v45-contract.e2e.spec.ts](../apps/api/test/v45-contract.e2e.spec.ts). The database suite also requires `RUN_V45_DB_TESTS=1` and an isolated PostgreSQL test database.
- `Not verified` means no execution evidence is recorded here. `Blocked` identifies an environment or contract gate that could not be completed. All 32 official V4.5 cases have current execution evidence in the QA report.
- The matrix covers V4.5 requirements in both source documents. POS-only requirements are deliberately excluded. The index below accounts for every official TC-01 through TC-32 and points to its test implementation.

## Scope, Conflicts, and Open Gaps

1. `FR-POS-*`, `FR-PRICE-*`, `FR-SALE-*`, `FR-PAY-*`, `FR-VOID-SALE-*`, `FR-PRINT-*`, and `NFR-PRINT-01` are POS requirements and intentionally have no V4.5 implementation or test mapping here. `NFR-REG-01` is a POS regression gate requiring these same 32 V4.5 cases; the index below records their current source status. This matrix does not authorize POS DDL, API, or UI work.
2. The Owner-approved update dated 2026-11-17 is reflected in Master Blueprint §2.3, the Receiving controller, RolesGuard integration tests, and batch detail UI: Owner, Admin Operasional, and Kepala Budidaya may create; Owner and Admin Operasional may VOID. Older role text remains in PRD `FR-REC-06/07` and Blueprint §§4.4, 4.5, and 5.2; these conflicts are noted, not silently rewritten.
3. TC-20 and TC-28 PASS using the injected dependency port and a test writer that locks the same batch row. The production V4.5 provider intentionally returns no dependency while no approved dependent transaction source exists; no POS, mortality, or feed table/API was added.
4. `current_stock` is derived from receipt quantity less Receiving VOID. SQL guard and TC-22 reject `completed` while computed stock is positive. Valid sales and mortality movement sources remain outside V4.5 until their approved modules exist.
5. Full PostgreSQL suite passed 121/121. Backup/restore rehearsal remains unverified because `pg_dump`, `pg_restore`, `createdb`, and `dropdb` are not installed on the audit host; see the QA gate report.
